# Blue Current 2.0 — Living Marine Ecosystem

**文档状态：** 生态升级设计与第一阶段接口约定  
**日期：** 2026-11-09  
**目标工程：** `Project/BlueCurrent`  
**本阶段范围：** 现有工程审查、生态设计、独立 `OceanCurrentField` 与 `HabitatZoneSystem` 及其测试。现有 Boids、捕食者、渲染和 UI 不在本阶段接线范围内。

## 1. 定位、目标与边界

Blue Current 2.0 的目标是把现有实时捕食—鱼群原型扩展为一个**风格化、可交互、可重复的温带岩礁海藻森林生态实验**。核心问题不再是鱼群能否形成动画，而是环境状态如何改变行为，生物如何消耗资源，以及资源变化如何反过来改变栖息地。

本设计采用教学与计算机动画取向的简化模型。参数具有明确单位和因果关系，但不声称代表某一处真实海域，也不用于生态预测、种群评估或渔业决策。视觉真实感、行为可解释性和数值稳定性优先于物种数量。

2.0 的完成标准由三类证据共同组成：同一海流场驱动多类对象，鱼群依据食物、威胁与栖息地选择行为，资源与种群指标来自可审计的模拟事件。仅有新模型、蓝色雾效或面板数值变化不构成生态升级。

## 3. 目标生态系统与物种清单

目标环境为近岸温带岩礁—海藻森林。光照、水深、海流与海底结构形成连续生境，海藻提供资源和三维遮蔽，小型群游鱼类在中层觅食，大型鲨鱼作为偶发顶级捕食者。鲨鱼模型解释为近岸活动的幼年或亚成体大型鲨鱼的风格化代理，不据此推断具体物种的精确猎物谱。

| 生态对象 | 2.0 中的角色 | 表示方式 | 当前状态与目标更新频率 |
| --- | --- | --- | --- |
| 群游鱼类 | 中层消费者；觅食、群游、避敌、避难 | 独立 Agent，沿用 SoA 与实例化渲染 | 已有运动；行为决策 10–15 Hz、转向与积分 60 Hz |
| 大型鲨鱼 | 搜索、接近、追逐、攻击与恢复 | 1 个独立 Agent | 已有基础 FSM；目标 60 Hz，决策可分频 |
| 海藻 | 初级生产者、遮蔽结构、海胆食物 | 每株/每斑块生物量 + 现有实例化网格 | 已有静态视觉；资源更新 1 Hz |
| 浮游生物资源 | 鱼类食物，随流输运、扩散与恢复 | 三维密度场，不逐粒建立 Agent | 未实现；目标 2–5 Hz |
| 海胆 | 底栖植食者，形成海藻退化实验 | 少量低频 Agent 或分礁斑块种群 | 未实现；目标 2–5 Hz |
| 悬浮颗粒 | 海流可视化，不参与食物网能量结算 | GPU/实例化视觉粒子 | 已有装饰粒子；后续与流场共用采样 |
| 海星、海獭 | 海胆捕食者的候选扩展 | 独立食物关系 | 不在本轮范围，不能借用鲨鱼逻辑替代 |

## 4. 食物关系与生态因果边界

箭头表示资源或能量关系，不表示每个消费者都会直接捕食下一层的全部对象。

```text
Light + nutrient proxy                 Light + nutrient proxy
        │                                      │
        ▼                                      ▼
Kelp / algae resource                 Phytoplankton resource
        │                                      │
        ▼                                      ▼
Sea urchin grazing                    Zooplankton / food field
        │                                      │
        ▼                                      ▼
Kelp biomass / cover change             Schooling fish
        │                                      │
        └────── habitat / refuge ──────────────┤
                                               ▼
                                        Shark predation
```

鱼类直接摄食浮游资源；海胆直接消耗海底海藻；鲨鱼只捕食鱼类。鲨鱼减少鱼类数量**不等于**鲨鱼控制海胆数量。若未来研究海胆—海藻生态级联，应另行加入海星或海獭等合理捕食关系。

资源变化必须形成闭环：鱼类摄食会减少局部资源，海胆摄食会降低海藻生物量，海藻退化会改变避难结构，栖息地变化再影响鱼类行为。与此同时，所有资源都要有恢复、输入或再殖机制，否则简化模型会在长时间运行中出现不可逆的数学归零，无法区分生态崩溃与数值伪影。

## 5. 连续空间分层与栖息地模型

栖息地是连续查询场，不是四个互不相通的容器。对位置 \(p=(x,y,z)\)，系统计算海床高度 \(f(x,z)\)、离底高度 \(h=y-f(x,z)\) 和水面下深度 \(d=y_{surface}-y\)。当前 `y_surface` 取模拟边界最大值 20 m，海床由现有 `floorHeightAt` 提供。

| 水层标识 | 默认主导离底区间 | 生态解释 |
| --- | --- | --- |
| `benthic` | `h≈0–2.5 m` | 海床、礁石基部、海藻固着器与底栖生物活动 |
| `lower-midwater` | `h≈2.5–9 m` | 下层鱼群、礁石边缘与低冠层避难 |
| `upper-midwater` | `h≈9–15 m` | 主要觅食与群游空间 |
| `surface-canopy` | `h≳15 m` | 高光水体；未来高冠层海藻可延伸至此 |

令 \(S(x)=smoothstep(x)\)，过渡宽度默认 1 m，并在 2.5、9、15 m 三个边界计算 \(s_0,s_1,s_2\)。权重定义为：

\[
w_b=1-s_0,\quad w_l=s_0-s_1,\quad w_u=s_1-s_2,\quad w_s=s_2
\]

由于边界有序且使用相同过渡宽度，恒有 \(s_0\ge s_1\ge s_2\)，所以即使自定义过渡区重叠，四项仍非负且之和恒为 1。`zone` 仅返回最大权重项用于调试和显示，行为计算应使用连续权重。区域边界随局部海床高度变化，因此不是全局水平硬切片。

第一阶段每次查询还提供以下真实几何/环境量。

| 字段 | 单位与范围 | 计算口径 |
| --- | --- | --- |
| `floorY` | m | 当前视觉/碰撞共用的海床函数 |
| `heightAboveFloor` | m | `y-floorY`，不隐藏越界负值 |
| `depth` | m | `surfaceY-y`，不伪装成压力或真实测深 |
| `lightIntensity` | 0–1，相对量 | \(I_0e^{-\beta\max(d,0)}\)，不是 PAR 测量值 |
| `kelpDensity` | 0–1，几何指数 | 各海藻垂直冠层贡献的最大值，不是生物量或实测覆盖率 |
| `reefProximity` | 0–1，几何指数 | 距最近礁石球面的平滑邻域权重 |
| `canopyTopY` | m | 水平软边缘内有非零冠层贡献时的最高海藻冠顶；无覆盖时为海床高度 |
| `inBounds` | boolean | 是否位于模拟水域；越界点仍可查询，不静默 clamp |

海藻几何由现有布局转换。`kelp_a` 采用基准高度 3.55 m、冠层半径 1.29315 m，`kelp_b` 采用 2.80 m、0.96785 m，均乘实例 `scale`。半径来自资产最大水平包围尺寸的一半，而不是固着器间距。圆柱加平滑边缘只是查询近似，不代替叶片碰撞。

当前 49 株中有 6 株位于模拟水平边界之外。第一阶段保留布局数据并依赖 `inBounds` 标记，避免把不可达位置选作未来避难目标。后续生成生态场景时应从布局源头裁剪，而不是让鱼群追逐不可达点。

现有海藻冠顶与鱼群活动高度错位是已确认基线问题。后续避难接入前必须选择并验证一种方案：提高海藻实例高度、调整鱼群与边界尺度，或重新设计资产。第一阶段不擅自改变现有视觉比例和鱼群轨迹，也不把 `surface-canopy` 权重解释为当前已有表层海藻。

| --- | --- | --- | --- |

| 浑浊度 | 相对 0–1 或消光 1/m | 视觉、捕食者检测 | 必须统一映射，视觉和感知不能各自调参 |

所有默认值都是可重复实验的初始条件，而非测量常数。进入 UI 的参数必须对应真实模拟输入；尚未接入的温度、氧气和生态统计不得以动态随机数填充。

## 7. 统一三维海流场

`OceanCurrentField` 是无内部时间状态的纯查询速度场。相同配置、位置与模拟时间必须得到相同结果。调用方提供输出数组，热路径不创建向量对象。

\[
u(p,t)=a_{bottom}(p)\,[u_{base}(p,t)+u_{vortex}(p,t)+u_{turbulence}(p,t)]
\]

最终模长限制到 `maxSpeed`，默认 1.25 m/s。该上限是数值保护，不应掩盖过强参数；测试同时扫描有限性与速度范围。

基础流默认方向来自海藻资产在 glTF 坐标中的静止倾斜方向，即 `[0.82,0,-0.57]` 归一化，速度默认 0.35 m/s。方向由构造函数归一化，零方向仅在基础速度为零时合法。基础流可叠加低幅时空调制，但第一阶段保持恒定，便于隔离测试涡流和扰动。

局部涡流由调用方根据礁石定义显式注入，避免在环境模块复制礁石常量。每个涡流具有中心、单位轴、半径和有符号切向速度。对轴向距离 \(s\)、径向距离 \(\rho\)、归一化半径 \(q=\rho/R\)：

\[
u_{vortex}=S\,q\,e^{1-q^2}e^{-s^2/(2R^2)}\,\hat t
\]

其中 \(\hat t\) 为轴与径向向量的单位叉积。轴心速度自然趋近零，正强度遵循右手定则。它是礁石附近局部环流的动画近似，并不模拟真实边界层或礁后脱落涡街。

小尺度扰动使用连续三角场。令 \(k=2\pi/L\)、\(\omega=2\pi/T\)、\(\theta=\omega t\)，默认 `L=6 m`、`T=24 s`、幅度 `A=0.08 m/s`：

\[
\begin{aligned}
u_x &= \tfrac A2[\sin(kz+\theta)+\cos(ky-\theta)]\\
u_y &= \tfrac A2[\sin(kx+2\theta)+\cos(kz-\theta)]\\
u_z &= \tfrac A2[\sin(ky+3\theta)+\cos(kx-2\theta)]
\end{aligned}
\]

各分量不依赖自身方向坐标，因此在未加近底衰减前散度为零，并且时间周期明确。这只是确定性的湍流代理，不是 CFD，也不给每条鱼、每株海藻或每颗粒子单独添加随机偏移。

近底衰减采用离底高度的 `smoothstep`，默认厚度 1.2 m。两个环境模块默认复用同一个 `floorHeightAt`，也允许在测试中注入海床函数。海流输出单位为 m/s；后续鱼类与鲨鱼通过阻力近似获得加速度，海藻读取方向/强度，资源场用于平流，颗粒用于视觉输运。视觉时间不得反向驱动物理。

## 8. 分层行为系统

现有 Boids 只保留局部运动协调职责。上层行为选择输出目标、权重和状态，底层转向仍受分离、对齐、聚合、障碍和边界约束。

| 层级 | 输入 | 输出 |
| --- | --- | --- |
| Ecological Goals | 生存、能量、食物、栖息地、群体状态 | 归一化需求与风险 |
| Behavior Selection | 威胁、食物价值、能量、同伴状态、避难可达性 | 行为状态、目标与权重 |
| Steering Behaviors | 当前目标及邻居 | Boids、Seek、Avoid、Refuge 等加速度 |
| Locomotion | 合加速度、速度限制、海流阻力 | 位置、速度、转向、尾鳍动画 |

鱼类状态包括 `Cruising`、`Foraging`、`Feeding`、`Schooling`、`Refuge Seeking`、`Fleeing` 和 `Recovery`。选择器可采用 Utility AI，但所有输入先归一化并固定口径。例如：

\[
U_{flee}=w_1R+w_2(1-D_{pred}/D_{safe}),\qquad
U_{forage}=w_3F+w_4H-w_5R
\]

高威胁时逃逸/避难优先，觅食不能因高食物价值压过生命危险。状态切换采用最小持续时间和滞后阈值，避免边界振荡。紧急避让仍在 60 Hz 更新，常规决策可按个体错相在 10–15 Hz 更新。个体差异由初始化种子生成并固定，不能每帧重新随机。

避难目标必须同时满足在边界内、不在礁石实体内部、目标可达、能提供海藻或礁石遮蔽。鲨鱼接近时，鱼群改变的不只是逃逸方向，也包括对安全生境的选择。当前高度/边界冲突解决前，不开启这一完整闭环。

鲨鱼后续扩展为 `Patrol → Detect → Approach → Stalk → Pursuit → Attack → Recover`。目标评分综合距离、相对速度、是否处于群体边缘、避难接近度和已消耗追逐时间。失败或猎物进入高遮蔽区后应结束追逐。浑浊度通过统一消光关系降低视觉检测距离，而非只改变画面颜色。

## 9. 资源、种群与生态数据流

浮游资源采用固定三维网格，建议初始约 `16×10×16` 个单元，覆盖同一模拟水域。每格存储 RU/m³，低频执行海流平流、扩散、恢复和鱼类消耗。半拉格朗日平流足够作为第一版，但必须限制 CFL、处理边界并保证资源非负。不要在 Three.js 场景图中为每个浮游生物建立对象。

海藻以株或小斑块保存归一化生物量 \(K\)。在海胆摄食之外加入小的再殖项，避免 \(K=0\) 后逻辑生长永远无法恢复：

\[
\frac{dK}{dt}=rK(1-K/K_{max})+\rho(K_{max}-K)-\gamma UK
\]

其中 \(r,\rho\) 为 1/s，\(U\) 为 ind/m²，\(\gamma\) 与单位匹配为 m²/(ind·s)。实际更新采用固定低频步长和非负解算/限幅，参数扫描必须检查异常振荡和不可逆归零。光照通过 \(r\) 或承载量影响生长，浑浊度通过光照产生间接作用。

海胆初版按礁石底栖斑块分组，以低频数量与位置代理产生摄食压力。数量变化必须与食物、设定死亡率或外部场景干预相关，不能仅根据海藻覆盖率反向伪造。海胆与海藻模型先于复杂繁殖遗传系统。

```text
FixedStepScheduler (60 Hz)
  └─ EcosystemManager accumulators
       ├─ ResourceField / FoodWeb / Population (1–5 Hz)
       ├─ Kelp biomass and habitat structure (1 Hz)
       └─ EcosystemMetrics (2–5 Hz)
  └─ Behavior selection (staggered 10–15 Hz)
  └─ Existing Boids update → flock swap → Predator update (60 Hz)
  └─ Real event ledger: feeding, capture, refuge occupancy
  └─ Rendering interpolates state; it never writes ecological state
```

资源消耗采用“请求—结算”两阶段：多个消费者先提交需求，资源系统按可用量比例分配并一次性扣减，防止更新顺序导致负资源或固定索引优先。每次成功摄食记录消费者、资源单元、实际摄入量和模拟时间。捕食捕获沿用真实捕获事件。统计只消费事件和明确状态，不读取动画颜色或尾鳍相位推测生态过程。

## 10. 水下环境表现

渲染升级首先建立与生态查询一致的空间光传输，再增加高成本效果。水下颜色不能简单统一混成蓝色。第一版按 RGB 使用 Beer–Lambert 近似：

\[
T_\lambda(d)=e^{-\beta_\lambda d},\qquad
C(d)=T_\lambda(d)C_{object}+[1-T_\lambda(d)]C_{water}
\]

各通道衰减系数是场景参数，并随统一浑浊度变化。近处主体保留对比度，远处逐渐融入水体颜色。初始系数属于美术调参，必须标为近似，不能写成某海域实测光谱。

体积光在基础衰减验证后实现，优先半分辨率或四分之一分辨率、有限步数与时间稳定上采样。焦散使用动态纹理投影到海床和近底资产，并受深度、光强和遮挡调制。悬浮颗粒、碎屑与气泡读取同一海流；气泡额外具有向上速度，海藻则在世界空间响应局部流向与速度。

现有 `KelpScatter` 的局部正弦摆动可以保留为高频细节，但主弯曲方向必须来自海流，不能继续让随机 yaw 决定主要环境方向。视觉更新可插值，生态状态只能由模拟层写入。性能验收继续在真实硬件 GPU 上执行；软件渲染截图只用于构图和错误检查。

## 11. 场景、随机种子与可重复性

以下是 2.0 目标场景配置，**当前尚未实现，第一阶段不会新增 UI 按钮或修改现有 `Scenarios.ts`**。

| 场景 | 建议种子 | 初始条件与观察重点 |
| --- | --- | --- |
| `healthy-kelp-forest` | `0x0ca17a11` | 高海藻生物量、低海胆密度、稳定海流、鱼群觅食；鲨鱼在外围巡游 |
| `predator-encounter` | `0x9e71c0de` | 相同生态基线，鲨鱼在鱼群附近释放；记录逃逸、避难、攻击与捕获事件 |
| `ecosystem-disturbance` | `0xd1570b1e` | 提高海胆初始密度，关闭鲨鱼以隔离变量；观察海藻、栖息地和鱼群分布变化 |

每个场景必须保存完整配置快照、布局种子、资源场种子、初始种群、预热步数和版本信息。重置场景应恢复所有生态状态，而不仅重置鱼群。相同版本、配置和固定步序列应产生相同事件日志与状态校验和；渲染帧率不得改变结果。

性能对照需区分当前完整 GLB 默认场景与 `?environment=bare` 干净基线。旧版本在程序化环境下得到的网格加速比或帧时间不能直接作为新生态场景结果。

## 12. 统计指标与计算口径

| 指标 | 计算口径 | 空分母/未实现行为 |
| --- | --- | --- |
| Fish Population | 当前 `alive=1` 的鱼数 | 已有真实数据 |
| Average Neighbors | 沿用现有搜索半径与活鱼邻居定义 | 保留现有口径 |
| Polarization | 活鱼单位速度合向量模长 / 活鱼数 | 无活鱼显示 N/A |
| Spatial Dispersion | 现有回旋半径（radius of gyration），必要时另报包围体积 | 不混用不同离散度公式 |
| Feeding Events | 实际资源扣减量大于阈值的事件数 | 事件未接线时不显示动态值 |
| Feeding Success | 成功摄食尝试数 / 已结束觅食尝试数 | 0 次已结束尝试显示 N/A |
| Predator Captures | 真实移除猎物事件数 | 已有真实数据 |
| Capture Rate | 捕获数 / 已进入有效攻击状态的攻击尝试数 | 0 次攻击显示 N/A |
| Habitat Utilization | 位于有效遮蔽区域的活鱼固定步数 / 活鱼总固定步数 | 另报高威胁子集，不能只统计动画状态 |
| Kelp Biomass | 各斑块归一化生物量按底栖面积加权平均 | 明确权重，不读视觉颜色 |
| Kelp Cover | 资源网格中覆盖面积 / 有效底栖面积 | 重叠冠层只计一次，不能简单求和超过 100% |
| Urchin Density | 活海胆数 / 有效底栖面积 | 面积口径固定为 m² |
| Simulation Time | 固定步生态与运动更新耗时，分开记录 | 不用渲染 FPS 推算 |

一次觅食尝试从选择具体资源目标开始，在成功摄食、超时、目标耗尽或威胁中断时结束。一次攻击尝试从进入有效 `Attack` 状态开始，以捕获、超时或目标丢失结束。这样成功率与捕获率都来自事件，而不是从状态持续时间估算。

## 13. 模块职责与计算频率

```text
src/
  simulation/       Existing fixed-step flock, predator, obstacles and spatial search
  environment/      OceanCurrentField, HabitatZoneSystem; later ResourceField/WaterColumn
  ecosystem/        Later EcosystemManager, FoodWebSystem, PopulationSystem, metrics
  behaviors/        Later utility selection and ecological steering adapters
  rendering/        Existing Three.js assets plus later underwater light/current consumers
  ui/               Existing panels; only real state and real events are exposed
```

| 模块 | 职责 | 建议频率 |
| --- | --- | --- |
| `OceanCurrentField` | 纯三维速度查询，无内部时钟 | 按需调用；无独立积分 |
| `HabitatZoneSystem` | 水层、深度、光照、海藻和礁石几何查询 | 静态时按需；生物量结构更新 1 Hz |
| `ResourceField` | 浮游资源平流、扩散、恢复和扣减 | 2–5 Hz |
| `FoodWebSystem` | 资源请求结算与真实事件 | 与资源更新一致，事件保留精确模拟时间 |
| `PopulationSystem` | 海胆等低频种群状态 | 2–5 Hz |
| `UtilityBehaviorSelector` | 行为评分、目标和滞后 | 每鱼 10–15 Hz，个体错相 |
| `BoidSystem` / `PredatorSystem` | 局部转向、碰撞约束、积分 | 固定 60 Hz |
| `EcosystemMetrics` | 聚合状态与事件账本 | 2–5 Hz |
| `KelpAnimation` / Particles | 消费模拟时间与海流，不反写生态状态 | 渲染帧率 |

`EcosystemManager` 是后续组合边界，拥有低频 accumulator 和生态模块生命周期。它不应复制 Boids 规则，也不让 UI 直接修改资源数组。第一阶段两个环境模块为复用现有海床而引用纯函数 `floorHeightAt`；后续可将地形函数上移到 `environment`，渲染与生态共同依赖，消除逆向分层依赖。

## 14. 测试、不变量与验收标准

每个模块先有不依赖 DOM 和 Three.js 的单元测试，再接入实体。第一阶段测试覆盖下表。

| 对象 | 必测性质 |
| --- | --- |
| 基础海流 | 默认方向归一化；无涡流/扰动时速度符合配置；同输入确定性一致 |
| 涡流 | 轴心为零、径向切向方向正确、正负强度反向、远离中心衰减 |
| 湍流代理 | 空间连续、时间周期成立、不同位置不是独立随机跳变 |
| 数值保护 | 扫描负坐标、边界外位置和大时间，输出有限且不超过 `maxSpeed` |
| 近底响应 | 海床处衰减、中层恢复；注入海床函数与采样结果一致 |
| 输出契约 | 只写 `out[0..2]`，其余元素不变，采样过程不分配向量 |
| 栖息地分层 | 任意高度四权重均在 0–1 且和为 1，过渡连续，主导区正确 |
| 栖息地几何 | 现有 49 株转换、冠顶/密度、礁石邻域、越界标记、零尺度退化输入 |
| 地形与光照 | 复用 `floorHeightAt`；深度增加时相对光强单调不增 |
| 回归 | 修改前 36 项测试继续通过，TypeScript 与生产构建通过 |

生态接线后还需执行资源守恒与非负测试、不同消费者顺序下的结算公平性、捕食/摄食事件口径测试，以及至少 30 分钟模拟时间的 soak test。soak test 要检查所有状态有限、资源不为负、鱼类不进入实体礁石或不可达边界、海藻不异常爆发/归零、海胆与海藻不出现由更新步长引起的持续数值振荡。

行为验收不能只靠截图。觅食阶段需要真实资源下降和成功事件，避难阶段需要高威胁鱼群的遮蔽利用率上升，捕食阶段需要攻击尝试与捕获事件可审计。每个阶段同时保存测试结果、运行截图、配置与具体变更清单；未接线的面板值显示 N/A 或不出现。

## 15. 性能风险与控制策略

| 风险 | 影响 | 控制策略 |
| --- | --- | --- |
| 每条鱼每帧扫描全部海藻/礁石 | 2000 鱼时产生不必要的百万级查询 | 当前 49+5 锚点可先线性验证；行为接入时建立水平网格并基准比较 |
| 行为选择每帧全量运行 | 增加 CPU 峰值与缓存压力 | 10–15 Hz、个体错相；紧急避让仍 60 Hz |
| 三维资源平流 | 网格内存、带宽和 CFL 稳定性 | 小网格、2–5 Hz、固定数组、限制步长，不创建对象粒子 |
| 每株海藻上传新几何 | GPU/CPU 同步开销 | 保持实例化，仅更新少量实例属性或 uniform |
| 全屏高采样体积光 | GPU 帧时间快速增加 | 先做 RGB 衰减，再低分辨率体积光并设质量档位 |
| 每帧指标与事件对象分配 | GC 抖动 | 预分配事件环形缓冲区，2–5 Hz 聚合 |
| 默认完整 GLB 场景 | 与旧基线不可比、启动成本更高 | 分别记录 bare 与 full 环境，硬件 GPU 独立验收 |
| 低频反馈数值振荡 | 生态错误被误判为动态效果 | 固定步长、非负结算、参数扫描和长时间测试 |

第一阶段模块尚未进入主循环，因此不能声称已经改善或降低主场景 FPS。接入后以相同机器、浏览器、资产模式、鱼数和场景比较 `simulationTime`、P95 帧时间、绘制调用和内存趋势。

## 16. 分阶段实施计划

| 阶段 | 范围 | 进入下一阶段的条件 |
| --- | --- | --- |
| Phase 0 | 代码/资产审查与本设计文档 | 基线事实、单位、因果边界和未完成项明确 |
| Phase 1 | 独立海流场、连续栖息地系统及单元测试 | 新测试和原 36 项测试通过，类型检查/构建通过，无内核改动 |
| Phase 2 | `EcosystemManager` 组合；海流先接颗粒/海藻，再以可开关阻力接鱼与鲨鱼 | 同种子可重复，grid/brute 等价，默认关闭时轨迹无回归 |

## 17. 第一阶段接口契约与非目标

本阶段新增文件为 `src/environment/OceanCurrentField.ts`、`src/environment/HabitatZoneSystem.ts` 及对应两个测试文件。模块不依赖 Three.js，不创建渲染对象，不修改主场景。

```ts
class OceanCurrentField {
  readonly config: OceanCurrentConfig;
  constructor(config?: Partial<OceanCurrentConfig>, floorAt?: FloorHeightFunction);
  sample(x: number, y: number, z: number, time: number, out: Float32Array): void;
  speedAt(x: number, y: number, z: number, time: number): number;
}

class HabitatZoneSystem {
  readonly kelp: readonly KelpAnchor[];
  readonly reefs: readonly ReefAnchor[];
  constructor(options: HabitatZoneOptions);
  sample(x: number, y: number, z: number, out: HabitatSample): HabitatSample;
  canopyTopAt(x: number, z: number): number;
}
```

`HabitatSample` 通过 `createHabitatSample()` 创建并复用；水层权重存储在同一个输出对象内。`kelpAnchorsFromLayout()` 接受结构兼容的现有海藻布局，不复制随机布局算法。配置在构造时校验，非法半径、周期、非有限值和零方向等尽早报错，而不是在动画中产生 NaN。

第一阶段明确不修改 `BoidSystem.ts`、`SimulationWorld.ts`、`PredatorSystem.ts`、`ObstacleSystem.ts`、`SimulationConfig.ts`、现有场景文件、渲染文件、UI 和资产。它也不新增场景按钮，不宣称鱼类已受海流影响，不输出虚构生态统计，不改变默认视觉效果。运行截图仅用于证明现有主场景可启动且无回归，而不是展示尚未接线的生态功能。
