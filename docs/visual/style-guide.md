# Visual — Style Guide

> 核实日期：2026-11-12。本文记录相对稳定的美术方向；实际灯光数值以 `UnderwaterLightingConfig.ts` 为准，当前缺陷与验收状态见 `../CURRENT_STATE.md`。

## 视觉目标

Blue Current 的目标是低饱和、青蓝色的实时温带水下生态观测场景。画面应通过近景材质与轮廓、中景吸收、远景低对比偏蓝形成深度，而不是把所有物体统一染蓝或不断加雾。鱼群、捕食者和礁石是主体，UI 是观测仪器，不应抢过场景。

主礁层级来自轮廓、局部受光、材质和附着密度，不靠单独打亮 Hero。丰富感应服务于可读性，不能用增加资产数量替代构图、接触关系和材质质量。

## 色彩管理与水体

水体保持线性空间、tonemapping 前合成，渲染器使用 ACES Filmic 和 sRGB 输出。禁止第二条雾链、tonemap 后混雾或重复 sRGBTransferOETF。`lighting=base` 用于隔离局部水体与光照效果，视觉对照必须保持同版、同机位、同种子和同时间点。

近景应保留鱼体、鲨鱼和岩石的材质识别；中景逐步吸收；远景降低对比并偏蓝。焦散、光柱和海雪是辅助层，不能形成明显贴片、重复条纹或遮蔽主体。光柱当前是平面与解析淡出，不应宣称完整体积渲染。

所有集中灯光与水体参数位于 `src/rendering/lighting/UnderwaterLightingConfig.ts`，属于美术指导值，不是实测海水光谱。修改时更新该配置与对照证据，不在各资产中复制全局光照参数。

## 材质与资产语言

礁石使用统一的岩石、层理、粗糙度和附着语言；Hero 可增强层理与单顶轮廓，D 保持双柱身份但降低次柱与装饰竞争。表生物覆盖用于区分主次，不是越密越好。`CoralScatter` 与 Reef Epibiont 是两套系统，调整一套时不能误改另一套。

海带和前景植物负责框景与生态层次，中央游泳通道保持可读。珊瑚、海草和装饰岩要与地形接触自然，远景细节成本随距离下降。Phase D 的海床重复纹理、植被变化和材质统一仍是后续工作，不能写成已完成。

生物动画应表现为连续身体/尾部运动、自然 banking 和 pitch，频率与速度及转弯相关。不得用刚性整体旋转代替全部游动，也不得新增第二套控制器同时写同一骨骼或位置。

## UI 视觉规范

当前 CSS token 以深海背景 `#071b26`、面板 `#0e2c39`、深面板 `#0a232e`、交互青 `#70c8d0`、主文字 `#dceced`、弱文字 `#8ba8b0` 为基础，捕食者状态使用暖橙色。数值使用等宽字体，正文使用 Inter/Noto Sans SC 等当前字体栈。

桌面结构为 56 px masthead、70 px transport、328 px Console；窄屏规则见 `src/style.css`。Console 在桌面是独立列，会改变画布宽高比；因此 UI 与构图必须一起验收 Console 开/关、窄视口和移动抽屉。

Observation 只呈现正式观测信息，Collision Debug、SDF 数值和调试线框属于 Laboratory。所有读数来自真实状态，不可测项为 N/A；不能为了面板完整而填假数据。

## 视觉修改完成条件

保留同版 Base/Final 或修改前后对照，记录资产前缀、URL、种子、时间点、视口、Console 状态和实际 renderer。软件截图可用于功能与画面对照，但硬件颜色、交互、性能和长时稳定性必须另验。构图变化同步 `composition.md`，新基线索引同步 `../validation/visual-baseline.md`。
